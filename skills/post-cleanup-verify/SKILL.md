# 清理核查（post-cleanup-verify）

## 适用场景
- 后渗透阶段收尾：逐项核对本次作业留下了什么（临时文件、上传物、账号、会话/隧道、监听端口、配置改动）。
- 产出「清理清单」与「残留项」，作为回环或结束技术测试的前置材料。

## 前提与边界
- **只读核验**：本技能只**确认现状**，不执行删除/断开/还原（那是人类在控制台或下一轮里做的动作）。发现残留 → 报告并请人类处置。
- 所有核验都必须**留在范围内**；范围外主机不测。
- 沙箱是 `--rm` 的一次性容器：容器内 `/tmp` 与前台进程随容器销毁，本就不构成残留——**要核查的残留主要在目标侧**（上传物、账号、会话、监听端口）。
- 沙箱里 **`ss` / `ps` / `netstat` 不存在**；用 `/proc`、`nc -z`、`curl` 替代。
- **`curl` 回连自检要慎用**：它会产生一次真实的出站连接到你自己起的监听。只在「必须确认某隧道/回连是否仍活」且人类知情时用；优先用不建立业务连接的 `nc -z`。

## 步骤

### 1. 先列清单：本次作业动过什么
```bash
jq -r '.actions[] | [.id, .kind, .target, .approved_at] | @tsv' /tmp/actions.json
```
期望：放行的每个动作、目标与时间。判据：**每个待核查项都能追溯到一次已放行动作**；追不到的动作先向人类确认，不要顺手去测。

### 2. 核查上传物/临时文件是否还在（HTTP 场景）
```bash
for u in /uploads/<本作业文件名> /tmp/<本作业文件名>; do
  printf '%s -> %s\n' "$u" "$(curl -sS -o /dev/null -w '%{http_code}' --max-time 5 "http://<目标>:<端口>$u")"
done
```
期望：`404`（已清）。判据：`200` → 记为**残留**；`403` → 记为「存在但受限，需人工确认」；**不要把 `404` 之外的任何码当作已清**。

### 3. 核查监听端口/会话是否已关闭
```bash
nc -z -w2 <目标> <监听端口>; echo "exit=$?"
```
期望：`exit=1`（拒绝）或超时。判据：`exit=0` → 该监听仍活，记为**残留**。
回连隧道：仅当上一步无法判定时，才在本地起一次性监听自检，并逐条记录：
```bash
timeout 5 nc -l -p <本地端口> >/tmp/cb.txt 2>&1 &   # 慎用：制造真实出站
sleep 1
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 3 "http://<目标>:<端口>/<回连触发路径>"; echo "exit=$?"
```
判据：本地监听收到连接（`/tmp/cb.txt` 非空或 `nc` 以 0 退出）→ **回连仍活**，立即停并请人类断开；无连接 → 记为「未观察到回连」，不等于已清（可能触发条件未满足）。

### 4. 核查账号/凭据类改动
只做**只读存在性检查**，不尝试创建或修改：
```bash
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 5 \
  -H 'Cookie: <本次作业可能创建的会话 Cookie>' http://<目标>:<端口>/<需登录端点>
```
期望：与清理前已知状态一致。判据：若「本应失效的凭据仍可使用」→ 记为**残留凭据**；报告里列凭据标识（不贴明文），请人类轮换/吊销。

### 5. 核查本地侧残留（容器内，通常随 `--rm` 消失）
```bash
ls -la /tmp 2>/dev/null
find / -xdev -newer /etc/hostname -type f -not -path '/proc/*' -not -path '/sys/*' 2>/dev/null | head -50
python3 - <<'PY'
import socket
for f in ("/proc/net/tcp", "/proc/net/tcp6"):
    try: rows = open(f).read().splitlines()[1:]
    except OSError: continue
    for l in rows:
        c = l.split()
        if c[3] == "0A":
            a, p = c[1].split(":")
            print(f, socket.inet_ntoa(bytes.fromhex(a)[::-1]) if len(a) == 8 else a, int(p, 16))
PY
```
期望：只有本次运行的临时输出，监听只出现沙箱自身必需的项（如 Docker 内嵌 DNS `127.0.0.11`）。判据：出现本作业未预期的监听 → 记为本地残留；若人类选择复用会话，把 `/tmp` 内容列入本地待清理项。

## 判读与去噪
- 「核验不到」≠「已清理」：连接超时可能只是目标过滤，不是端口关闭。用 `exit` 码区分「拒绝（1）」与「超时」。
- `404` 只说明该 URL 路径不存在，不证明文件系统物理删除；以能否再次读取业务效果为准。
- `200` 且内容是旧内容 = 残留；`200` 且是默认页 = 可能只是路径回退，标注不确定性。
- 回连自检可能**重新激活**一条本该断开的会话，或留下审计痕迹——这就是「慎用」的具体含义；能不用就不用。

## 常见失败
| 现象 | 真实原因 | 处置 |
|---|---|---|
| `ss`/`ps` command not found | 镜像里没有 | 用 `/proc/net/tcp`、`nc -z`、`curl` 替代，不要试图安装 |
| 所有核验项都超时 | 目标已下线或不再可达 | 记为「无法核验」，不是「已清理」；请人类确认目标状态 |
| 回连自检把会话「打活」了 | 触发路径仍有效且监听仍活 | 立即停，报告「仍可回连」，请人类按预案断开 |
| 上传物返回 403 | 存在但访问受限 | 记为「待人工确认」，不要尝试绕过 |

## 不做的事
- 不执行任何删除、断开、吊销、还原（只读核验；处置由人类做）。
- 不做超出「本次作业动过的东西」的枚举。
- 不在范围外主机上核验；不用回连自检替代常规只读判定。
- 不把「未观察到残留」写成「已清理干净」。

## 产出（交给下一步）
- 清理清单：逐项 `动作 → 目标 → 核验命令 → 结果 → 判定（已清/残留/无法核验）`。
- 残留项：类型（文件/端口/会话/凭据/配置）、位置、证据、建议处置。
- 无法核验项与原因；本地侧残留（若会话复用）。
