# 回环与交接（post-loop-handoff）

## 适用场景
- 后渗透阶段已有影响边界与清理核查结果，要回答两件事：**开新一轮迭代（回环）还是结束技术测试**？以及**交接给下一轮情报收集什么**？
- 本技能只产出**候选建议**；是否回环、是否结束、以及范围修订，都是人类的决策。

## 前提与边界
- 本阶段**不执行**内网侦察与横向移动；它们属于下一轮（情报收集 / 利用验证），必须在修订后的范围与新放行下进行。
- **回环的前置条件是范围修订**：内网发现的资产默认不在授权范围内。未经人类修订范围，不得以任何方式开启新一轮（设计里这是硬闸门：起点范围版本未变即视为未修订）。
- AI 只能生成**交接草稿**；人类审阅、编辑、确认后才成为交接包。不要假设建议会被原样采纳。
- 判据以「证据 + 是否产生新未知区域」为准，不以「感觉还有东西可挖」为准。
- 可出网（2026-10-05 起）：外部情报核对能自己做，但**外部资料不是目标证据**——标来源、未证实按假设；确需人类判断的仍写清楚要谁做什么。

## 步骤

> **容器是一次性的**（`--rm`）：`/tmp/boundary.json` 与 `/tmp/cleanup.json` **只在那一条命令内存在**，
> 而且它们**不会由"前两个技能"留在容器里**（前一阶段是别的会话、别的容器）——上游结论是从**记忆/报告**
> 里读到的，必须由你在**同一条命令里**先落成 json 再消费（`cat > /tmp/boundary.json <<'JSON' … && jq …`）。
> 分开写会得到 `No such file or directory`（2026-10-06 实测）。

### 1. 汇总前两技能的结论
```bash
jq -s '.[0].boundary as $b | .[1].cleanup as $c | {boundary: $b, cleanup: $c}' /tmp/boundary.json /tmp/cleanup.json
```
期望：边界条目与清理/残留结果合到一处。判据：**没有边界条目与清理结论就不进入判定**——先补齐，再谈回环。

### 2. 抽出「新未知区域」候选（回环的实质依据）
```bash
jq -r '.boundary[] | select(.verdict == "in-scope") | [.asset, .kind, .source_access] | @tsv' /tmp/boundary.json
```
期望：一列可归类的新资产。判据：**每个候选都要能写出来源**（从哪个入口/哪条访问发现）；写不出来源的归为推断，不进回环建议。

### 3. 判定信号（回环 vs 结束）
```text
回环（建议开新一轮）只要满足任一条：
  A. 边界核查发现了新资产/新服务，且它们不属于上一轮范围；
  B. 存在只有在新范围内才能验证的未决线索（新凭据可达面、新信任路径）。

结束技术测试（建议收尾）需同时满足：
  C. 上一轮范围内已无未覆盖的测试面（覆盖缺口已说明并接受）；
  D. 没有产生新的、范围外可继续的未知区域；
  E. 清理核查的残留项已登记并交给人类处置。
```
```bash
jq -r '.boundary | {new_assets: [.[] | select(.verdict=="out-of-scope")] | length, unresolved: [.[] | select(.verdict=="unconfirmed")] | length}' /tmp/boundary.json
```
期望：范围外新资产数与未决线索数。判据：命中 A 或 B → 建议回环，并在交接材料里给出范围修订点；同时命中 C、D、E → 建议结束技术测试。**两者都不命中**（有线索但不足以判定）→ 建议回补（rollback）到更早阶段补验证，不要硬凑回环。

### 4. 生成范围修订点（回环的必备输入）
```bash
jq -n --arg a '<asset>' --arg s '<source>' \
  '{asset: $a, source: $s, proposal: "include|exclude", rationale: "<为什么>"}'
```
期望：人类修订范围所需的最小字段。判据：每条含 `asset`、`source`（发现来源）、`include/exclude` 建议与理由；**授权依据由人类填写**，Agent 不代填、不索要凭据。

### 5. 产出交接材料清单（交给下一轮情报收集）
```bash
jq -n --slurpfile b /tmp/boundary.json '{leads: [], new_assets: [], scope_amendments: [], retained_access: []}'
```
期望：四类材料就位，缺项显式标「缺」。判据：交付物**不含范围外资产的主动测试请求**——只描述「发现了什么、来源在哪」，不含对它们的扫描/连接指令。清单：
1. 未决线索：现象 + 证据引用 + 上一轮为何没继续 + 下一轮验证的最小条件。
2. 新资产：`asset / 类型 / 来源（入口→发现路径）/ 建议 in-out / 未知面`。
3. 建议范围修订点：上一步的结构化条目（供人类在 ScopeManager 里增删）。
4. 仍需保留的访问上下文：仅在下一轮需要且人类已确认时保留。

## 判读与去噪
- 「还有服务没测」不自动等于回环：若它本就在上一轮范围内，那是**覆盖缺口**，应回补而不是开新一轮。
- 「发现新主机」也不自动等于回环：必须先由人类写进新范围版本；在此之前它只是候选。
- 交接是**压缩与引用**：给结论与证据引用，不搬原始输出；下一 Agent 可按引用检索记忆。
- 边界里的「越界候选」在回环前**不入范围、不测试**；它们是人类修订范围时的输入，不是下一轮默认目标。

## 常见失败
| 现象 | 真实原因 | 处置 |
|---|---|---|
| 无法判断回环还是结束 | 缺少边界条目/清理结论 | 回到前两步补齐；不靠猜测填判定 |
| 建议回环但范围未修订 | 回环前置条件未满足 | 只提交范围修订点，等人类修订并生成新范围版本后再回环 |
| 交接材料里混入范围外动作 | 把「候选资产」写成了「下一轮目标」 | 改为描述性条目，去掉测试指令 |
| 线索只能用外网核对 | 沙箱可出网（2026-10-05 起） | 能查就查并标来源；证据强度仍以目标实测为准 |

## 不做的事
- 不自行决定回环/结束，不自行修改范围，不生成授权依据。
- 不在本阶段做内网侦察或横向移动。
- 不把候选资产默认当作已授权目标；不在交接材料里附带范围外的执行计划。
- 不搬原始数据，只给结论与引用。

## 产出（交给下一步）
- 判定建议：回环 / 结束技术测试 / 回补，附命中的信号（A–E）。
- 交接材料清单：未决线索、新资产（含来源）、建议范围修订点、需保留的访问上下文。
- 覆盖缺口与残留交接项（来自清理技能）。
